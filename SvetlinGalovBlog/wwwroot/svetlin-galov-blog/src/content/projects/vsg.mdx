<Section label="The Challenge">

## Velocity without structure

Two separate design systems existed across the company: an external component library powering internal back-office tools and a custom design system used for customer-facing experiences. Both lacked shared governance, clear documentation, and contribution workflows.

Similar components were rebuilt multiple times across squads. Visual and behavioral inconsistencies accumulated. Design-to-development handoffs required repeated clarification. Without stronger foundations, every new feature risked increasing design debt.
    
    
    <TextCard bulletNumber={"01"} heading={"Consolidating fragmented component systems"}>
        Auditing components across internal tools and customer-facing products, identifying duplicated patterns and inconsistencies, and merging the two existing design systems into a unified foundation.
    </TextCard>
    
    <TextCard bulletNumber={"02"} heading={"Redesigning token architecture"}>
        Restructuring the token architecture and aligning naming conventions with engineering implementation, making it easier for developers to map design decisions directly to code.
    </TextCard>
    
    <TextCard bulletNumber={"03"} heading={"Building governance and contribution workflows"}>
        Introducing a contribution process allowing designers across squads to propose improvements while maintaining accessibility and consistency standards. This included guidelines, proposal templates, review checkpoints, and documentation tied to releases.
    </TextCard>
    
    <TextCard bulletNumber={"04"} heading={"Supporting cross-team adoption"}>
        Running internal training sessions, workshops on component usage and accessibility standards, improved documentation and examples, and close collaboration with developers on implementation details.
    </TextCard>
    
    <TextCard bulletNumber={"05"} heading={"AI-assisted documentation workflows"}>
        Introducing AI-assisted workflows to generate documentation drafts, component explanations, and internal guides, significantly reducing the time required to update documentation while keeping standards accessible for teams.
    </TextCard>

## Design systems as organizational infrastructure

For me, design systems are not UI libraries. They are organizational infrastructure that allows teams to move faster together.

My focus was ensuring the system reduced design debt instead of generating more, accelerated delivery without sacrificing consistency, created shared language between design and engineering, and supported long-term maintainability of the platform.
